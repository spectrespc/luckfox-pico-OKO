# Подтверждённые функции OKO

Функции и возможности прошивки OKO, проверенные на реальном стенде и имеющие
статус **работает**. Непроверенные и частично проверенные возможности — в
`FEATURES_UNVERIFIED.md`; паспорт платформы, общие примечания и команды проверки —
в `FEATURES.md`; доказательства — в `VERIFIED_FUNCTIONS.md`.

Статус на 2026-11-09.

### Примечания

- YOLO/NPU: `librknnmrt.so` — 1.6.0, драйвер `rknpu` 0.9.8 совместим (проверено
  2026-11-06: hot-swap, три перезагрузки и 2-часовой soak с YOLO и AIISP). Модель
  обязана быть INT8 `.rknn`, вход — ровно `yolo.input_width`×`yolo.input_height`;
  иначе активация отклоняется. Модель 640×384 INT8 (2.6 МиБ) собирается
  `tools/rknn-toolkit2/` и в образ не входит — после прошивки её загружают через
  `/api/models`. Кадры кольца — 640×384 NV12, `max_frames` — жёсткий потолок
  пакета; квота загрузки 3 МиБ. `source: vpss3` занимает последний VPSS-канал и
  потому несовместим с IVS/MJPEG/четвёртым потоком — санитайзер переводит на
  `vi0`. `source: vi1` (selfpath) на этой сборке привёл к зависанию платы и
  заблокирован — см. `FEATURES_UNVERIFIED.md`. Ящики в поток/JPEG не рисуются.
  AIISP и YOLO на `vpss3` работают одновременно (стенд, демо 640×640:
  main 30–33 fps, NPU 28%, без пропусков).
- Второй рантайм RKNN 2.3.2 (`librknnmrt2.so`, SONAME изменён): включается
  `yolo.runtime: 2`, модель собирается `tools/rknn-toolkit2/Dockerfile.toolkit2`
  и активируется без рестарта. AIISP/RockIVA продолжают работать на 1.6.0 в
  том же процессе; переключение `runtime=1` ↔ `runtime=2` проверено, 2-часовой
  soak без утечек. Активация модели «чужого» рантайма отклоняется с причиной.
  mAP 2.x-модели на размеченном наборе не измерялся.
- RGA: im2d `importbuffer_fd` на `rknpu` 0.9.8 принимает MMZ- и dma-heap-fd,
  поэтому `yolo.convert: rga` конвертирует NV12→RGB888 на RGA (CPU `divinus`
  ~35.6% → ~29.4% при 5 fps 640×384, fps не падает, 2-часовой soak без
  зависаний) с откатом на CPU при ошибке. Легаси `c_RkRgaBlit` и блит по
  `malloc`-памяти по-прежнему непригодны (SIGSEGV/зависания). Кольцо кадров
  живёт в MMZ и отображается через `mmap(fd)` (виртуальный адрес
  `MB_Handle2VirAddr` для MMZ-блока валиден только на первые 4 КиБ).

### Notes

- YOLO/NPU: `librknnmrt.so` is 1.6.0 and the `rknpu` 0.9.8 driver is compatible
  (verified 2026-11-06: hot-swap, three reboots and a 2-hour soak with YOLO and
  AIISP).
  The model must be INT8 `.rknn` with an input exactly
  `yolo.input_width`×`yolo.input_height`; otherwise activation is refused. The
  640×384 INT8 model (2.6 MiB) is built by `tools/rknn-toolkit2/`, is not part
  of the image and is uploaded via `/api/models` after flashing. Ring frames are
  640×384 NV12, `max_frames` is a hard package cap, and the upload quota is
  3 MiB. `source: vpss3` takes the last VPSS channel and is therefore
  incompatible with IVS/MJPEG/a fourth stream, so the sanitizer falls back to
  `vi0`. `source: vi1` (selfpath) hangs this board and is blocked — see
  `FEATURES_UNVERIFIED.md`. With `yolo.boxes=1` a 2BPP overlay region draws
  detection boxes on the main stream only (two colours, 4-pixel line
  alignment); the
  event JPEGs stay clean. See the YOLO row and the boxes note below.
  AIISP and YOLO on `vpss3` run together (bench, 640×640 demo: main 30–33 fps,
  NPU 28%, no drops).
- A second RKNN 2.3.2 runtime (`librknnmrt2.so`, distinct SONAME) is available
  via `yolo.runtime: 2`; models are built with
  `tools/rknn-toolkit2/Dockerfile.toolkit2` and activated without a restart.
