# Спецификация протокола I²C — контроллер двигателей STM8S103

> 🇬🇧 [English version](PROTOCOL.md)

## Параметры шины
- Скорость: стандартный режим (100 кГц)
- Адрес ведомого: 0x60 (7 бит)
- Адрес записи: 0xC0, адрес чтения: 0xC1
- Внешние подтягивающие резисторы: 4.7 кОм на SDA/SCL

## Формат транзакции
- **Только запись**: `[START][0xC0][CMD][MOTOR][PARAM...][STOP]`
- **Запись+чтение**: `[START][0xC0][CMD][MOTOR][REPEATED START][0xC1][DATA...][!ACK][STOP]`

## Справочник команд

| Команда | Запись (payload) | Чтение (payload) | Описание |
|-------|-------------|--------------|-------------|
| 0x01 | [cmd][motor][steps_hi][steps_lo] | — | Переместить двигатель на N шагов (int16 BE, дополнительный код) |
| 0x02 | [cmd][motor][spd_hi][spd_lo] | — | Задать скорость (uint16 BE, шагов/с, макс. 5000) |
| 0x03 | [cmd][motor] | — | Остановить двигатель |
| 0x04 | [cmd][motor] | [pos_0..pos_3] | Запрос текущей позиции (int32 BE) |
| 0x05 | [cmd][motor] | [status] | Запрос состояния (0=IDLE, 1=RUNNING, 2=ERROR) |
| 0x06 | [cmd] | — | Программный сброс контроллера |
| 0x07 | [cmd] | — | Переход в I2C-загрузчик (форк OKO) |
| 0x08 | [cmd] | [role][maj][min][pat] | Роль (0=app, 1=boot) и версия (общая с загрузчиком) |
| 0x09 | [cmd][motor][pos_0..pos_3] | — | Принудительно задать логическую позицию (int32 BE) без движения; игнорируется в RUNNING (2.0.2+) |
| 0x0A | [cmd] | [mode][state][wake_ms][0][ent_hi][ent_lo][w_i2c][w_timer] | Состояние сна по тишине I2C и счётчики (2.2.0+; в 2.3.2 `wake_ms` — гранулярность 1 мс, `w_timer` — пробуждения таймером) |
| 0x0B | [cmd][mode][idle_s] | — | Включить/выключить сон: `mode` 0=выкл 1=вкл, `idle_s` 0=дефолт 3 с (2.2.0+); ответа нет, проверка чтением 0x0A |
| 0xFF | [cmd] | [maj][min][pat] | Получить версию прошивки (3 байта) |

## Подробные примеры команд

### Запрос версии
```bash
i2ctransfer -y 7 w1@0x60 0xFF r3
# Response: 0x02 0x02 0x00 (версия 2.2.0; тестовая плата 2.3.0)
```

### Задать скорость
```bash
# Set focus motor speed to 500 steps/sec
i2ctransfer -y 7 w4@0x60 0x02 0x00 0x01 0xF4
```

### Перемещение двигателя
```bash
# Move focus motor +100 steps
i2ctransfer -y 7 w4@0x60 0x01 0x00 0x00 0x64
```

### Получить позицию
```bash
# Get focus motor position
i2ctransfer -y 7 w2@0x60 0x04 0x00 r4
# Response: [pos_0..pos_3] (int32 BE)
```

### Получить состояние
```bash
# Get zoom motor status
i2ctransfer -y 7 w2@0x60 0x05 0x01 r1
# Response: 0x00 (IDLE), 0x01 (RUNNING) or 0x02 (ERROR)
```

### Остановить двигатель
```bash
# Stop zoom motor
i2ctransfer -y 7 w2@0x60 0x03 0x01
```

### Программный сброс
```bash
# Reset controller
i2ctransfer -y 7 w1@0x60 0x06
```

### Задать позицию (обнуление шкалы)
```bash
# Force the focus position to 0 without driving the motor
i2ctransfer -y 7 w6@0x60 0x09 0x00 0x00 0x00 0x00 0x00
# Проверьте чтением 0x04; запись в EEPROM произойдёт в течение ~1 с
```

**Известный дефект (KI-042):** в 2.0.2/2.1.1 движение, заканчивающееся ниже
нуля, оставляет логическую позицию с испорченным старшим байтом (`-1`
читается как `0xFBFFFFFF`), хотя мотор проходит заданное число шагов. Не
используйте отрицательное значение `GET_POS` для управления; после homing
отправляйте `SET_POS(0)`.

### Управление сном (0x0A / 0x0B)

```bash
# Включить сон после 3 с тишины шины (idle_s = 0 — значение по умолчанию)
i2ctransfer -y 3 w3@0x60 0x0B 0x01 0x00
# Чтение: режим, состояние, гранулярность пробуждения (мс), резерв,
#          эпизоды сна (BE), пробуждения по I2C, пробуждения по таймеру
i2ctransfer -y 3 w1@0x60 0x0A r8
# Ответ: 0x01 0x00 0x01 0x00 0x00 0x2A 0x03 0xFF
```

`state`: 0 — бодрствует, 1 — сохраняет EEPROM, 2 — взведён, 3 — спит
(виден в момент обслуживания кадра, разбудившего контроллер).

`wake_ms` (байт 2) — гранулярность пробуждения в миллисекундах.  В 2.3.2 это
один тик TIM4 (1 мс).  В 2.2.0/2.3.0 байт отдавался в единицах по 10 мс
(`40` = 400 мс, слайс Active-halt) — при обновлении хоста учитывайте это
различие для прошивок ≥ 2.3.2.

`w_timer` (байт 7) — число пробуждений по таймеру (saturating в 255; в
2.3.2 — тики TIM4, поэтому быстро доходит до 255 и служит признаком «сон
реально работал», а в 2.2.0/2.3.0 это были пробуждения AWU).

## Ответы write-команд (загрузчик ≥ 1.1.0)

Write-команды (`0x11`–`0x14`) отвечают **двумя байтами**: `[status][эхо
команды]`.  Хост обязан сверить эхо: если пришёл статус прошлой команды,
кадр не дошёл до загрузчика.  До 1.1.0 ответ был одним байтом, и потерянный
кадр выглядел как успех (KI-075).

## Энергосбережение (сон по тишине I2C)

- Источник простоя — любой завершённый кадр.  После `idle_s` секунд тишины,
  при отсутствии RUNNING-мотора, незавершённой транзакции и грязного EEPROM,
  приложение переходит в **Wait mode** (`WFI`) на один тик TIM4.
- В Wait mode тактирование fMASTER продолжается: TIM4 каждую 1 мс будит ядро
  и его обработчик перезагружает IWDG, а I2C-slave отвечает штатно — сон не
  задерживает кадры хоста.  Тактовая частота ядра между тиками снята, поэтому
  ток ниже, чем в Run, но выше, чем в Halt.
- Почему не Active-halt: на стендовом экземпляре STM8S003F3P6 узел AWU не
  считает (регистры `AWUEN/TBR/APR` читаются/пишутся, но `AWUF` не
  выставляется даже через MSR-измерение LSI), поэтому HALT нечем разбудить и
  через ~0,5 с срабатывает IWDG-сброс.  Проверено на стенде 2026-11-21
  (см. `KNOWN_ISSUES.md`, KI-077).
- `system_ticks` в Wait mode идёт: тиковые таймауты (включая 2-секундный
  self-reset I2C) работают как обычно.
- Episode-счётчик `entries` растёт один раз на период тишины (вход в сон), а
  не на каждый тик; `w_i2c` считает кадры, пришедшие во сне; `w_timer` —
  таймерные пробуждения (saturating).
- По умолчанию: выключено в продуктовой сборке (`BOARD=oko`, 2.2.0),
  включено на тестовой плате (`BOARD=test`, 2.3.2).  `oko-motor flash` и
  `/api/flash` выключают сон перед `ENTER_BOOT`.
- Держите в голове: пока хост опрашивает контроллер чаще, чем раз в `idle_s`
  (например, divinus опрашивает `/api/firmware` каждые ~2 с при пороге 3 с),
  сон не наступает — это ожидаемо, сон предназначен для окон, когда AP не
  опрашивает привод (в т.ч. на время suspend).

## Обработка ошибок
- Неизвестные команды игнорируются (без NACK); 0x07 в этом форке — ENTER_BOOT.
- Ошибки I2C (AF/BERR/OVR) → автоматический сброс модуля
- Таймаут 2 с без активности → сброс модуля
